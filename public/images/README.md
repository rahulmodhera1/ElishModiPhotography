# Where the photographs go

Everything in here except this file is a **placeholder**. Each one is a flat
tonal panel at the right aspect ratio, generated by
`scripts/generate-placeholders.mjs`, so the layout has real files to reserve
space with during development. None of them should survive launch.

## Swapping in real work

Replace a file **in place**, keeping the filename. Nothing else changes:

```
public/images/
├── brand/
│   ├── logo-dark.svg      for light backgrounds
│   ├── logo-light.svg     for dark backgrounds (the nav and footer use this one)
│   └── favicon.png        512x512
├── hero/
│   └── hero.jpg           the single strongest frame in the book, 2400x1600 or wider
├── about/
│   └── portrait.jpg       a real photo of Elish, portrait crop, roughly 4:5
├── offerings/             the six service cards. Wide cells are 4:3, narrow are 4:5
│   ├── baby.jpg
│   ├── child.jpg
│   ├── family.jpg
│   ├── portraits.jpg
│   ├── vehicle.jpg
│   └── landscape.jpg
├── work/                  the portfolio itself, one folder per category
│   ├── baby/
│   ├── child/
│   ├── family/
│   ├── portraits/
│   ├── vehicle/
│   └── landscape/
└── og/
    └── og-image.jpg       social share card, exactly 1200x630
```

## Adding a photo to the portfolio

Two steps.

1. Drop the file into `public/images/work/<category>/`.
2. Add one entry to the `photos` array in `src/lib/work.ts`:

```ts
{
  src: "/images/work/family/family-04.jpg",
  category: "family",
  alt: "The Okonkwos on the fire escape, late afternoon, backlit",
  width: 1200,
  height: 1500,
  scale: "tall",
},
```

Valid categories are `baby`, `child`, `family`, `portraits`, `vehicle` and
`landscape`. TypeScript will reject anything else.

The filter chips, the counts, the grid rhythm and the lightbox all read from
that array. There is no second place to update.

- **`width` and `height` must be the file's real pixel dimensions.** They are
  what reserves the box before the image loads. Wrong numbers mean the page
  jumps as photos arrive.
- **`alt` is real description, not the filename.** It is read aloud by screen
  readers and shown under the image in the lightbox.
- **`scale`** places the tile in the grid: `full`, `wide`, `half` or `tall`.
  Mix them. A column of identical tiles is the thing this grid exists to avoid.

## Before uploading

- Export at roughly 2000-2400px on the long edge. Next.js resizes down per
  breakpoint, so anything larger is wasted bytes and anything smaller looks
  soft on a retina screen.
- Export as **JPEG with an sRGB profile.** Serving is WebP, converted at build
  time.
- Keep the six category folders balanced. The grid reads best with at least
  three or four frames per category.
